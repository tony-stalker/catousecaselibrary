The 60-Minute Platform Demo

A first demo to a mixed IT and security audience is not an hour of console time. It is ten minutes of listening, two slides, thirty-five minutes across seven capabilities in one console, ten minutes of questions and five minutes agreeing what happens next. This page is the running order, the timings, the bridge lines between segments, the tenant staging checklist and the cut plan for when the clock gets away from you.

Why a running order

The hour is mostly not demo time

Sixty minutes sounds generous until you divide it. Ten minutes go to introductions and setting the scene, ten to questions, five to next steps. That leaves thirty-five minutes of console time for seven capabilities: five minutes each, no more. Without a running order the first two segments eat twenty minutes, ZTNA gets squeezed, DEM is dropped, and the one thing a network lead came to see never appears.

The aim of the hour is not to show everything. It is to leave the room with one idea — one cloud platform, one policy engine, one console — proven from seven angles, and to convert that into a decision to run a proof of value with an agreed scope. The PoV itself follows the frame in Running a Cato PoV: scope workshop, written success criteria, a fixed end date and evidence collected as it lands. This page gets you to the point where that conversation can start.

The one idea

Every flow — user to internet, user to private application, site to site — passes the same single-pass engine in the Cato PoP. Each of the seven segments is that engine seen from a different angle. Say it at minute five and let every transition repeat it.

Tenant staging checklist

What must be true before the call

A five-minute segment has no time to generate its own evidence. Every proof point in the running order depends on something that already exists in the demo tenant: a rule with a visible block, an event from the last few days, a dashboard with data in it. Walk this list the day before, in order, and fix what is missing.

  1. TLS inspection on for the demo user group

    Security → TLS Inspection

    The SWG, CASB and DLP segments all show decisions made on decrypted traffic. Confirm an inspect rule covers the demo user or group, and that the sensitive-category bypasses sit above it so you can answer the privacy question from the same screen.

  2. An Internet Firewall rule with a visible block

    Security → Internet Firewall Monitor → Events

    One user-aware category or application rule with a non-zero hit count, and at least one block event from the demo user in the recent window. Segment 1 opens on the rule and closes on the event.

  3. Recent IPS and anti-malware events on the Threats Dashboard

    Monitor → Threats Dashboard Security → IPS Security → Anti-Malware

    The dashboard must show activity in the chosen time range, with at least one blocked threat you can drill into. An empty dashboard is the worst thing segment 2 can open on.

  4. Cloud Apps Dashboard populated

    Monitor → Cloud Apps Dashboard Monitor → App Analytics

    Enough recent SaaS traffic that the dashboard shows a spread of applications and risk scores, including something unsanctioned you can point at for the shadow IT beat.

  5. One DLP rule with a recent incident

    Security → DLP Configuration Monitor → Data Protection Dashboard

    A rule that stops an upload containing a recognisable data type, and an incident from the demo user in the recent window so the dashboard and the event list both have something to show.

  6. A demo user with a posture profile, one allow rule over the implicit block

    Access → Users Access → Device Posture Security → WAN Firewall

    The demo user is visible under Users, carries a posture profile, and matches one WAN Firewall allow rule with nothing beneath it but the implicit block. Check the allow rule has a recent event from the compliant device and that a block event exists from the non-compliant one.

  7. One Private App through a connected App Connector Group

    Access → App Connectors Access → Private Apps

    The connector group shows connected, the private application is published by domain, and the policy names one allowed user and one who is not. Test both from a client before the day: the allowed user reaches it, the other cannot resolve it.

  8. Experience Monitoring with a user showing a degraded hop

    Home → Experience Monitoring

    A user whose score for one application is visibly lower than the rest, with a path analysis that shows where the latency sits. If nobody is degraded on the day, show the score and skip the drill — see the cut plan.

If you are running late

The cut plan

Cut in this order and no other. Each cut buys back a few minutes without removing a segment from the story, because the bridge lines still work.

Cut 1 · CASB to the dashboard only

Show the Cloud Apps Dashboard, name the shadow IT and the risk score, skip the Application Control rule. Two minutes instead of five.

Cut 2 · Fold DLP into CASB

Show the DLP incident from the same events screen you are already on for CASB, and skip the DLP Configuration walk. The bridge line still lands.

Cut 3 · DEM score only

Show the per-user, per-app score and say what path analysis would add. Drop the hop-by-hop drill.

Never cut these

If the audience is security-led, ZTNA and App Connectors stay in at full length. If the audience is network or ops-led, DEM stays in at full length. Take the time from the other cuts or from the questions block, not from the segment the room came for.

Park it

A question that takes more than one sentence to answer gets written on the agenda slide's parking list, in the questioner's words, and answered at minute 45 — parked questions first, in the order written. Say that out loud when you park the first one, so the room knows the list is real.

Build the deck

Generating the facilitation deck

The two scene-setting slides and the segment dividers do not need to be built by hand. The Build a demo presentation card on the library home page has a Platform demo (60 min) preset that selects the seven segment pages in running order, names the deck and switches the Compact option on. Compact exports a cover, an agenda carrying each segment's minute slot, then for every segment a divider slide (its bridge-in line) and a what-we-will-show slide (its CMA click-path), and a closing slide — about seventeen slides, which is the right size for an hour where the console does the talking. Untick Compact to get the full four slides per segment (adds the why and diagram slides).

Use the agenda slide's parking list for the questions you park, and keep the scene-setting picture above as the last thing on screen before you open the console. Speaker notes on every slide carry the bridge lines, so the deck can also be presented from a second screen.

Questions you will get

Six first-demo questions

Short answers for the questions block. Each links to the depth page that carries the detail; if the question goes further than the page does, say so and park it for the PoV.

Is it one agent?

Yes. The Cato Client (Windows, macOS, iOS, Android, Linux) connects the user to the nearest PoP, where the full single-pass stack — ZTNA, FWaaS, SWG, IPS, anti-malware, TLS inspection — is applied to every flow. On Windows, macOS, iOS and Android it is always-on, so there is no unprotected state to fall back into; Linux connects but without the always-on enforcement.

Securing the Hybrid Workforce

What about sites without Sockets?

A Socket is the preferred way to connect a site: it manages the last mile, selects the best PoP automatically and re-homes if one becomes unavailable. A site behind a third-party firewall or in a public cloud can connect over IPsec to a configured PoP instead — narrower, but the same policy once the traffic arrives.

IPsec Site Design · Cloud Connectivity

How is TLS inspection handled for privacy?

Inspection is a rulebase with bypasses evaluated first: the sensitive categories (health, finance, government) and embedded operating systems are bypassed as the baseline, and whoever owns privacy signs off the inspect scope before any traffic is decrypted. Pinned and client-certificate applications are exempted by explicit bypass rules.

TLS Inspection: Staged Rollout Playbook

What happens when a PoP is unavailable?

The Socket evaluates its links and moves to another PoP automatically, with preferred primary and secondary locations if the customer wants to steer it. Socket sites and Clients connect to the nearest available PoP (an IPsec site stays on the PoPs you configured for it), and every PoP runs the full software stack, so policy does not change with the PoP.

Resilient Site Design · SD-WAN

Where is the data stored?

Event data lives in the Cato Data Lake for the licensed retention period — 3, 6 or 12 months — and is deleted from the Cato Cloud afterwards; it can be exported to S3, Azure Blob or a SIEM at no charge. For data residency and processing-location questions, point to Cato's published security, compliance and privacy page rather than answering from memory.

Event Logs & the Cato Data Lake · Compliance

How long does a PoV take?

As long as the scope needs and no longer: one scope workshop, written success criteria, a weekly 30-minute sync and a fixed end date agreed up front. The packaged AI Visibility Assessment runs on a four-week clock and is the reference for how tightly the frame can be held.
