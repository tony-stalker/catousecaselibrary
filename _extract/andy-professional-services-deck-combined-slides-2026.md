## Slide 23: Inspection Prerequisites
- Forcing traffic to fall back to TLS over TCP for Inspection
- |
- QUIC/GQUIC = 🚫 Blocked → HTTPS = ✅ Inspectable
| Rule Name | Source | App/Category | Service/Port | Action |
| Block GQUIC Apps | Any | 📂 GQuic | Any | 🚫 Block |
| Block QUIC Services | Any | Any | 🛠️ QUIC | 🚫 Block |
- Blocking forces fall back to TLS over TCP (inspectable)
- Blocked in Internet Firewall rules
- Auto-added on TLS Inspection Enablement
NOTES: This brings us to our first prerequisite for enabling TLS inspection. 
Since QUIC and gQUIC can’t be inspected, they should be blocked. 
By doing this, we force traffic back to TLS over TCP so it can be inspected. 
The good news is, Cato handles this automatically whenever TLS inspection is enabled. 
The table here outlines our best-practice firewall rules for blocking QUIC and gQUIC on the internet fw policy
Some organizations go further and block QUIC and gQUIC at the source — 
by updating browser settings through endpoint management tools to use HTTPS over TCP.

## Slide 24: Inspection Prerequisites
- Additional Considerations
- |
- 🔒 Block ECH (encrypted Client Hello)
- Forces fallback to unencrypted SNI
- Block DoH, DoT, QUIC + cloudflare-ech.com
- Preserves hostname visibility
- 🕵️ Block Anonymizers
- Block Anonymizer URL Category
- Block Apple Private Relay
- Block services like DoH & DoT
- 🔀 Consider Path Symmetry
- Enabling TLS Inspection activates a TCP Proxy
- This can break asymmetric routing across Cato & MPLS paths
- 🔹 Off-Cloud Traffic
- Prioritise Off-Cloud/Alt-WAN rules above complex ones to bypass PoP/TCP proxy and prevent TLS failures.
NOTES: There are a few other considerations to make TLS inspection work effectively.
First, we need to block Encrypted Client Hello on services like Cloudflare to maintain hostname visibility. To achieve this, we recommend blocking DoH, DoT, QUIC, and the domain cloudflare-ech.com
Secondly, we recommend blockling anonymizers on your network, this includes the anonymizer URL category, Apple Private Relay, and services like DoH and DoT.
Third, consider path symmetry. Enabling TLS inspection activates a TCP proxy, which can break asymmetric routing across Cato and alt-wan paths if not accounted for.
if using off-cloud traffic rules - we should consider network rule placement to prevent unwanted TCP inspection.
You’ll also find some helpful resources at the end of the deck if you’d like to dig deeper into these requirements.

NOTES: In this next section we’ll look at strategies for enabling TLS inspection gradually
- There are two main approaches: 
- On the left, we see the source-based approach. This usually starts with a pilot group — a small set of users, VLANs, or pilot sites, with wider rollout actioned in batches to additional user groups or sites.

- On the right, we can see the destination-based approach. Here, we start by enabling inspection for Internet traffic by slowly adding outbound URL categories. With the final phase expanding to for full east–west inspection
- Often both approaches are combined allowing destination category enablement for pilot groups
When selecting pilot candidates, it’s important to include a good cross-section of the business based on business functions — 
this will allow use to identify issues early in an isolated manner where they cab be addressed before wider deployment. 
Finally, strong communicationd and feedback from our pilot users is key to minimizing impact as we move to a wider rollout

NOTES: Rather than enabling TLS inspection all at once, Cato recommend a phased rollout by category.

This structured, staged approach reduces user disruption and introduces inspection slowly to avoid overwhelming IT teams with reported user issues

## Slide 139: Branch Default Gateway Takeover

- Cato advertises:
  - 0.0.0.0/0 (default route) and system prefixes to the branch edge router
- Branch edge router advertises:
  - Site-specific prefixes to Cato
- Internet-bound traffic is steered through Cato with advanced security inspection enforced
- WAN traffic continues to be routed via the existing network
- DNS architecture review required
